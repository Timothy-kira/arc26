- **分数：** 按引擎公式算的 RHAE。每关得分 min(115, 100·(人类步数/AI步数)²)，按关卡序号加权；表中是每个游戏得分的平均值。
- **LLM：** 本地和 Kaggle API 版都用 Dots（`dots3-note-prev`，托管 API）。旧架构默认思考关闭、每局 20 分钟；新架构思考打开。
- **波动：** 单次运行的结果波动很大，同一个游戏两次能差到 0 关和 7 关。所以从 v10 起用 Kaggle 上两组同时跑、每个游戏 3 局的对照来下结论。

- **GPU 预算：** 比赛 GPU 上合计每秒只有几百个 token，一局能用的 token 大约十几万，所以每步平均要压到 1000 个 token 左右。对策：
  - 例外才思考；
  - 图的历史做折叠；
  - 超时后接续作答，不丢弃已经生成的思考；
  - 25 局同时跑，提高 GPU 的总吞吐。
- **结论（初步）：** 过了的关，步数基本等于或少于人类。瓶颈是时间：难的一步要写 2 万到 4 万个 token 的思考，所以 25 分钟一局只能走 15–30 步。
- **调参游戏（按人类步数挑选）：** 简单 cd82（171 步）、中等 tu93（462 步）、最难 wa30（1843 步）。目标是 Dots 在这 3 个游戏上平均 30 分以上，达到后再跑完整的 25 个。
- **评估方式：** 本地容器会重启，长评估一律放到 Kaggle 上：`arc26-agent-api` 跑迭代集，`arc26-agent-val-api` 跑验证集，`arc26-agent-dev` 用比赛 GPU。
